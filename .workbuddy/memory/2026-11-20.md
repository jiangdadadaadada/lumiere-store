### 修掉的两个真 bug
1. **白底阈值太松**（`tools/whitebg.py`）
   `white_ratio` 用 `>=235` 判白 → **238 灰底（#eee）被当成"已经是白底"直接跳过转换**，
   商品页还是灰底。改为 `>=250`，并新增 `is_flat()` + `flatten_to_white()`：
   近纯色图直接换底为纯白（对纯色图做 AI 抠图没意义）。
2. **落盘竞态**（`server.js`）
   `saveStore()` 有 120ms 去抖，响应先发、盘后写 → 客户端读到的还是旧库。
   拆出 `saveStoreNow()`，采集入库两个接口在返回响应前**同步写盘**。

### 测试
`tools/ext_test.js` 重写 [4][5][6][7] 段，**64/64 通过**：
- 一键流程：采集 4 个夹具商品 → 自动白底 → 直接入库 → 落盘校验（db.json + webp + 四角纯白）

## 第三轮：草稿箱（江少："采集的商品都进草稿箱进行初次编辑"）

### 需求
采集不再直接入库 → 先进草稿箱编辑 → 确认后发布上架。

### 改动（4 处）
1. **`server.js` 数据层**：`mem` 加 `drafts: Map`，load/save 接 `db.json` 的 `drafts` 字段。
2. **`server.js` API**：
   - `/api/collect/batch` 语义改为"批量写草稿"（仍在采集阶段就 `enforceWhiteProduct` 转白底）
   - `GET /api/drafts` 列表；`PUT|DELETE /api/drafts/:id` 编辑/丢弃；
   - `POST /api/drafts/:id/publish` 发布（调 core 的 POST /api/products，成功后删草稿）
   - 注意路由顺序：publish 正则必须先于通用 `:id` 正则匹配
3. **`extension/`**：接口地址不变，只改文案（"入库"→"存草稿箱"，按钮"采集当前页并入库"→"采集到草稿箱"）
4. **`admin.html`**：侧栏加"草稿箱"入口（带数量红点）+ `view-drafts` 视图 + renderDrafts/editDraft/publishDraft/dropDraft。
   `loadAll` 并行加 `api('/api/drafts')`。
5. **`product-form.html`**：支持 `?draft=ID`，抽出 `fillForm()` 复用；草稿模式保存走 `/api/drafts/:id`；
   新增"保存并发布上架"按钮（`saveThenPublish()`）。

### 验证（全通）
- 采集 2 款 → 草稿 2、商品数不变(9)；编辑草稿名/价/SKU 成功；
- 发布 → 商品 9→10、草稿减 1、SKU 用编辑时填的值；丢弃清理后 9 款 0 草稿。
- 白底验证：草稿图路径 `/assets/img/collected/CV-*.webp`，四角 RGB(255,255,255)。
- 测试数据已清理，无残留。

- 草稿 ID 前缀 `DRAFT-`；发布时删掉 id/status/createdAt，用 `sku` 字段作正式商品 SKU。
- 采集阶段的白底转换保留（草稿里就是白底图），不是发布时才转。
